# 第 7 课：智能指针（`Box`、`Rc`、`RefCell`）与内部可变性

> 面向 Go 开发者的核心对照：Go 里只要取 `&x`，逃逸分析会自动把对象放进堆里、交给 GC 回收；Rust 没有 GC，所以把“堆分配”“多所有权共享”“运行期可变借用”拆成了三种边界极清晰的智能指针，**按需付费**。

## 1. 三大核心智能指针速览

| 类型 | 所有权模型 | 借用检查时机 | 线程安全 | 典型用途 |
|---|---|---|---|---|
| `Box<T>` | 单一所有者（堆上） | 编译期 | 取决于 `T` | 递归类型（链表/树）、大对象防栈溢出、`Box<dyn Trait>` |
| `Rc<T>` | **多所有者共享**（引用计数） | 编译期（仅不可变） | 否（单线程） | 图/树节点共享、只读配置共享 |
| `RefCell<T>` | 单一所有者（**内部可变性**） | **运行期**（违规 panic） | 否（单线程） | Mock 对象、缓存、与 `Rc` 组合成 `Rc<RefCell<T>>` |

> 多线程版本下节课学：`Arc<T>`（原子引用计数）+ `Mutex<T>` / `RwLock<T>`。

## 2. `Box<T>`：把数据显式放到堆上

为什么递归类型必须用 `Box`？因为编译器在编译期需要知道每个类型的**固定栈大小**。直接写 `enum Expr { Add(Expr, Expr) }` 会导致无限大小，包一层 `Box<Expr>` 后栈上只占一个指针宽度（8 字节）：

```rust
enum Expr {
    Num(i32),
    Add(Box<Expr>, Box<Expr>),
}
```

## 3. `Rc<T>`：单线程引用计数共享

- `Rc::clone(&a)` **不会深拷贝数据**，只是把引用计数 +1（O(1)），推荐写成 `Rc::clone(&a)` 而不是 `a.clone()`，一眼就能看出这是廉价的计数递增。
- 当最后一个 `Rc` 离开作用域、计数归零时，堆内存自动释放。
- 警惕**循环引用内存泄漏**：如果 A 持 `Rc<B>` 且 B 持 `Rc<A>`，计数永不归零；打破循环用 `Weak<T>`（`Rc::downgrade`）。

## 4. `RefCell<T>` 与 `Rc<RefCell<T>>`：内部可变性

有时你手里只有不可变引用 `&self`（比如实现某个只读 trait 或被多个 `Rc` 共享），但内部确实需要修改状态（如记录调用日志、缓存计数）：
- `cell.borrow()` -> 返回 `Ref<T>`（运行期读锁，可多个并发）
- `cell.borrow_mut()` -> 返回 `RefMut<T>`（运行期写锁，独占；若此时已有任何读/写借用存活，会**运行期 panic**！）
- 黄金搭档 **`Rc<RefCell<T>>`**：单线程下实现“多个所有者共享 + 可修改”。

## 5. `Deref` 与 `Drop`

- **`Deref`**：让智能指针像普通引用一样自动解引用（这就是为什么 `&String` 能自动变成 `&str`，`&Box<T>` 能自动变成 `&T`）。
- **`Drop`**：析构函数（离开作用域自动触发，类似 Go 的 `defer` 但绑定在类型上，永远不会忘写）。

## 6. 本课练习安排

1. 先运行随堂演示：`cargo run --example smart_pointers_demo`
2. 依次完成：
   - `src/ex01_box.rs`：用 `Box<Expr>` 实现递归算术表达式树求值 + `Box<dyn Trait>`
   - `src/ex02_rc.rs`：用 `Rc<T>` 共享只读数据并观察引用计数变化

3. 运行 `cargo test && cargo clippy` 验收，完成后推送到 `lesson07` 分支。
